# ADR-02 pin used by I04

**Status: accepted by the maintainer on 2026-10-29.**

The storage spike on `adr02-storage-spike` (`61ea2a0`) did not select an
engine. The maintainer accepted this pin for I04:

- `rusqlite` 0.41.1 with the bundled amalgam, SQLite 3.54.1, which is after
  the WAL-reset fix in 3.51.3
- `journal_mode=WAL` and `synchronous=FULL`
- `fullfsync=ON` on Apple, because `synchronous=FULL` there is not
  `F_FULLFSYNC`
- one owning process, via an OS lock beside the database

A fault-injection VFS covers the software power-loss model: a failed sync
discards bytes since the last successful sync, and a torn write leaves a
short prefix, then further writes fail. Reopen must show no partial
publication and must not ack the failed operation. A machine or VM power-cut
is still not done. The ledger does not admit a batch; the caller still has
to validate before `publish`.
