# ADR-02 pin used by I04

**Status: accepted by the maintainer on 2026-10-29.**

The storage spike on `adr02-storage-spike` (`61ea2a0`) did not select an
engine. The maintainer accepted this pin for I04:

- `rusqlite` 0.41.1 with the bundled amalgam, SQLite 3.54.1, which is after
  the WAL-reset fix in 3.51.3
- `journal_mode=WAL` and `synchronous=FULL`
- `fullfsync=ON` on Apple, because `synchronous=FULL` there is not
  `F_FULLFSYNC`
- one owning process, via an OS lock beside the database

A fault-injection VFS covers the software power-loss model: a failed sync
discards bytes since the last successful sync, a torn write leaves a
short prefix, and a disk-full write fails without persisting anything; each
then makes further writes fail. Reopen must show no partial
publication and must not ack the failed operation. The WAL-reset regression
scenario (checkpoint TRUNCATE, then further publications, then an armed
fault) is an explicit test in the T04 corpus since B6. A machine or VM
power-cut is still not done.

`publish` admits a batch before it stores one. It verifies the signature,
recomputes the batch id, checks the stream step and parent lamports, and
leaves a missing parent pending. Equivocation unpublishes the stored claimant
and does not publish the new one. Native scope is still not checked, so a
batch with native artifacts is refused.
